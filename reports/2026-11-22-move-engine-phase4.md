# move-engine Phase 4: skill logic export (+ Blade Adept automation)

2026-11-22 · branch `feat/move-skills` · how-to: tools/move-engine/README.md "Skill logic export".

## What changed
- **Skill blocks** (`tools/move-engine/moves/<family>/skills.js`): a skill's rules as plain data next to its move: `props`,
  the effect / reaction row tables, module flags and (new) embedded Active Effects by name. `bind` ties a page slider to a
  field, so the approved slider value is the skill's value.
- **`move-engine.js export <family> [skill…]`**: `--check` dry-runs the blocks in the snapshot runner (per copy: what differs
  from the world after its migrations, plus the skill validator); `--write <key>` writes the migration + manifest entry.
  One game-side helper does both: `data-migrations/_move-engine-skill-seed.js` (world item + every actor / token copy).
- **Round trip (stage 1)**: Sonic Blow and Gunblade (Passive) blocks match the world exactly, every logic field.
- **Forward pilot: Blade Adept** (Weaponmaster heroic; Keren, Rogue, Weaponmaster copies). Text-only parts now automated, one
  AE "Blade Adept" on every copy (Keren's live flying-reach AE from the 11-22 session is updated in place, not duplicated):
  - +1 DEF and +1 M.DEF while a **melee dagger** is equipped (`aeEquippedWhen("melee_dagger", "1")`, 0 otherwise);
  - the dagger **counts as brawling, sword and thrown** for skills and effects: new AE key `weapon_category_alias`
    (`melee_dagger: brawling, sword, thrown`), read by HAS_WEAPON_CATEGORY_* / USED_WEAPON_CATEGORY_IS_*, the equipment AE
    gate `aeEquippedWhen("sword", …)`, and the melee-vs-Flying rule (`scripts/battle-director/weapon-alias.js`);
  - flying reach kept (`can_target_flying_with: dagger`).
  - The gate also learned weapon-category tokens (`dagger`, `melee_dagger`, `ranged_bow`, …); before, it knew only
    shield / armor / weapon / martial_armor.
- Migration **`2026-11-22-blade-adept-automation`** (generated by `export class-skills blade_adept --write`).

## Verified
- `export class-skills --check` (fresh snapshot of today's world): only the intended differences (AE created on 3 copies,
  Keren's AE gains 3 changes, flying reach unchanged); validator clean.
- Runner test, Keren after the migration:

  | case | DEF | M.DEF | counts as sword / brawling / thrown | melee-vs-Flying with dagger |
  |---|---|---|---|---|
  | unarmed | 11 | 13 | no | yes (AE) |
  | melee dagger equipped | **12** | **14** (+1) | **yes** | yes |
  | dagger, Blade Adept AE off | 11 | 13 | no | no |
  | same dagger set to Ranged | 11 | 13 | no | (ranged anyway) |

  A test AE `aeEquippedWhen("sword", "5")` opened with the melee dagger (through the alias) and stayed shut without Blade Adept.
- `weapon-alias.test.mjs` unit test passes.
- Real-server first boot (sandbox copy of the real world, V12): migration ran, 4 copies written, 0 exceptions; sandbox torn down.
