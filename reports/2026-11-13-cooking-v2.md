# Cooking v2 (v1.0.604)

Heads-up for sarunphat: the party hot-pot gets new rules, a Yaminabe (risk) mode, wheels for ties and recipe overlaps, a flavor-pip sequence and a cookbook. Only the two cooking files change (`cooking-system/cooking-api.js`, `cooking-system/cooking-ui.js`). The camp activity still calls `FUCompanion.api.cooking.start({ cookerUuid })`, unchanged. The cook's Group Check (INS + DEX, open helpers) is unchanged too.

Approved mockup: https://claude.ai/artifact/4DJ4kNCuUJj9USjwJMAZsE

## What changes at the table (Oni's rulings, 2026-11-13)

- **The chart is a flavor wheel.** Bitter, Sweet, Sour, Salty, Umami. Neighbours on the chart harmonize; tastes across the chart clash. Every link is worth 2 potency:
  - **Resonance** (the same taste again): +2.
  - **Harmony** (neighbours): +2.
  - **Clash** (across the chart): −2.
  - Four or more different tastes **muddle** the pot, and it becomes a **Spoiled** dish (a debuff until the next rest).
  - Recipes skip all of this.
- **Dish names** add a style and the featured ingredient, e.g. "Hearty Honeyed-Savory Moonshroom Stir-fry". The buff is still the matrix dish's. Style comes from the most common ingredient **kind** (Sea / Meat / Monster / Garden / Pantry / Arcane, a map in `_Cooking Config`). The featured ingredient is the rarest of the winning taste. The meal Active Effect carries the full name.
- **Ties spin the taste wheel.** On a 2-2 tie, or when a muddled pot needs to know "whose taste ruined it", the wheel lands on one taste. The odds follow the rarity of each taste's ingredients. Mysterious Hot-Pot is no longer cooked (its item stays in the world, unused).
- **Recipes.** Named recipes (exact items) beat pattern recipes (a core of `{ taste }` or `{ kind }` entries). When two or more recipes in the same layer fit, the **recipe wheel** spins, weighted by the rarity of the named items (named) or by specificity (pattern). Unseen dishes show as ???. This replaces `priority`, which the content script removes from the recipes. No pattern recipes ship yet.
- **Yaminabe (risk mode).**
  - Every pot opens in Hot Pot. Only the **cook** sees the 🌑 Yaminabe button, and only until anyone locks an ingredient.
  - It's one way: a confirmation window, then an ink-blot transition into a dark theme.
  - Picks are hidden from everyone but the player who made them. Throws happen with the lights out, then a reveal.
  - Yaminabe adds +2 potency. Potency 15+ reaches a **Dark Delicacy** (a tier above 3, Yaminabe only).
- **Flavor pips** (cooking phase): after all ingredients are in, one pip pops per ingredient, then they resolve left to right.
  - Fuse: a combo sound ladder, Success_1 → success2 → Fabula_Point.
  - Bounce on a clash: Parry.
  - Muddle: emotion_down.
  - Perfect Harmony (everything fused): bond_level_2.
  - One system badge shows "Resonance +2" / "Harmony +2 · Clash −2" / "Combo ×2" with the running total.
- **Cookbook**: a small book icon in the panel header. It covers 30 taste × style entries, 10 fusions, recipes, Dark Delicacies, Spoiled dishes and Goop. A near miss unlocks a partial hint ("Toxic Puffer + ?").
- **Result card**: who threw what (featured ingredient ringed), the potency breakdown, tier stars, and "New in the Cookbook". Spoiled plays failed_1 and Goop plays Disappointment; good dishes keep bond_level_3.

## Code

- `cooking-api.js`:
  - `resolve()` is still pure. New fields on the outcome: `kind` dish|dark|spoiled|recipe|goop, `key`, `displayName`, `parts`, `wheel`, `near`, `featured`, `style`.
  - New: `requestYaminabe(sessionId)`.
  - `applyDish(id, targets, { displayName })` names the meal AE.
  - `start()` and `devSim()` now share one `_runSession`.
  - The GM's stand-in picks for offline players run **one at a time**. Concurrent GM pickers replaced each other; this was pre-existing in v1.
- Socket (same channel):
  - New: `COOKING_MODE_REQ` (any → GM), `COOKING_MODE` / `COOKING_MODE_DENIED` (GM → all), `COOKING_RESOLVE` (GM → all, carries the wheel the host already decided).
  - `COOKING_ANIMATE` now carries `mode` and each contribution's taste/rarity/kind.
  - `COOKING_STATE` is **redacted** while the pot is Yaminabe.
  - `COOKING_HOVER` is not sent in Yaminabe.
- `cooking-ui.js`: replaced (port of the mockup). Public API kept: `openMainPanel`, `openPicker`, `applyState`, `_applyHover`, `runAnimation`, `showResults`, `playSfx`, `closeAll`, `getMain`. New: `setMode`, `runResolve`. The dark theme is a body class `oni-cook-yami`, removed on close.
